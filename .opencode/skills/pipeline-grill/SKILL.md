# Скилл «Grill» — вопросы владельцу до работы (dev-pipeline)

**description:** Grill-фаза исполнителя конвейера dev-pipeline: прежде чем править код, агент добивается общего понимания карточки/задачи — сначала изучая код и вики самостоятельно, затем задавая владельцу МИНИМУМ блокирующих вопросов через файлы Tasks\Вопросы с ожиданием ответа (agents/wait_answer.py). По мотивам grill-me / grill-me-checkpoint (github.com/RobMitt, EricTechPro). Use when executing a plan card or task A-NN and the постановка is ambiguous, or when asked to clarify requirements before coding.

## Зачем

Запрещённые вопросы → догадки → переделки и «тупняк». Разрешённые по правилам вопросы →
решения зафиксированы, работа идёт с первого раза. Владелец управляет ключевыми решениями,
не микроменеджментом.

## Принципы (по приоритету)

1. **Сначала ищи сам.** Всё, что отвечает код, вики проекта (`<project>\.opencode\wiki\index.md`),
   план или конфиг (`pipeline.yaml`) — узнай сам. Вопрос «где лежит X?» — запрещён.
2. **Вопрос только о выборе, а не о факте.** Спрашивай, когда нужно решение владельца:
   подход/интерфейс/формат данных, противоречие в постановке, изменение границ задачи.
3. **Один вопрос за раз**, каждый — с 2–4 конкретными вариантами и рекомендацией
   («рекомендую A, потому что …»). Варианты «да/нет» без альтернатив — плохо.
4. **Лимит: максимум 2 вопроса на карточку.** Не влезло в лимит — выбери самый дешёвый
   вариант сам и пометь допущением.
5. **Каждый ответ фиксируется до следующего шага** (чекпоинт ответов — источник истины).

## Механика для неинтерактивной сессии (opencode run)

1. Создай файл вопроса `Tasks\Вопросы\<КАРТОЧКА>_<ГГГГММДД-ЧЧММСС>.md`:

   ```markdown
   ---
   карточка: 3.2
   ---
   # ВОПРОС 3.2: формат снимка для shared-загрузчика?
   ## Контекст
   Проверил: rooms.html читает camelCase, ThreeJsExport — PascalCase (файлы, строки).
   ## Варианты
   - A) camelCase + нормализация при загрузке (рекомендую: меньше правок стендов)
   - B) PascalCase как в C# DTO (правки трёх страниц)
   ## Ответы
   ```

2. Заблокируйся ожиданием одной командой (таймаут из конфига раннера, обычно 1200 c):

   ```
   python -X utf8 "<dev-pipeline>\agents\wait_answer.py" "<путь к Q-файлу>" --timeout 1200
   ```

3. Результат: `rc=0` — ответ появился в секции «## Ответы», следуй ему строго;
   `rc=1` — таймаут: продолжай по наиболее обоснованному варианту, каждое допущение
   помечай в отчёте строкой `ASSUMPTION: <что предположил и почему>`.
4. Ответ может прийти и сообщением в канал сессии (панель → SSE) — если ты его получил,
   продублируй краткое решение в Q-файл секцией «## Ответы» сам.

## Recap (обязателен)

Перед отчётом сведи итог grill-фазы:

```markdown
## Решения (grill)
- 3.2/Q1: формат снимка = camelCase+нормализация (ответ владельца 2026-08-22 14:05)
- ASSUMPTION: единицы кривых — метры (ответа не дождался, см. ThreeJsElement.cs:41)
```

Без этой секции отчёт считается неполным, карточка не принимается.
