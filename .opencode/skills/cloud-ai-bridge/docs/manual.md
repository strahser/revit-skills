# Мануал: взаимодействие с облачным ИИ через LocalAssitent

Локальный ассистент (`E:\ПлагиныРевит\LocalAssitent`) — это Selenium-агент, который
автоматизирует браузер (Edge) и «роутит» информацию к мощному облачному ИИ:
DeepSeek Chat (chat.deepseek.com) и Qwen (chat.qwen.ai). Облачные модели существенно
сильнее свободных/локальных — особенно для больших задач с контекстом проекта.

## Зачем это нужно

| Проблема | Решение |
|----------|---------|
| Локальный/бесплатный ИИ слаб на сложных задачах | Облачный DeepSeek/Qwen мощнее |
| Файлы проекта большие, вручную не вставить | LocalAssitent грузит файлы drag-and-drop |
| Ручное копирование контекста — ошибки и время | Автоматический роутинг через браузер |
| Ответы большие — нужен надёжный сбор | Скрипт сохраняет ответ в .md автоматически |

## 1. Подготовка контекста (merge_docs)

Перед отправкой облачному ИИ собери контекст проекта в ОДИН файл:

```bash
cd E:\ПлагиныРевит\LocalAssitent
python tools/merge_docs.py E:\ПлагиныРевит\HeatLossRevit2 --ext .cs --output context.txt
```

Сводный файл включает сводную таблицу (имя файла, строк, путь). Облачные ИИ хорошо
понимают такой формат, но для переноса между namespace лучше подавать **инвентарь**
(путь | строки | namespace | зависимости), а не полный код.

### Правила подготовки

- Размер файла: < ~800 КБ (умеренно; при превышении — чанкинг по 10-15 файлов)
- Кодировка: UTF-8 (без BOM для .txt, с BOM для .cs — это разные случаи!)
- Добавляй сводку зависимостей (что тянет MainApp, NuGet-пакеты, XAML)

## 2. Формирование ТЗ (по docs/task-template.md)

ТЗ — самый важный шаг. От качества ТЗ зависит, применим ли ответ.

### Структура ТЗ (кратко)

1. **Контекст** — что за проект, куда переносим, версии, git-хэш последнего коммита
2. **Цель** — что должен сделать облачный ИИ (одна задача!)
3. **Входные данные** — инвентарь файлов (НЕ полный код!)
4. **Формат ответа** — таблицы решений / скрипты / секции
5. **Контракт полноты** — SUMMARY + маркеры END OF FILE
6. **Ограничения** — что НЕ делать (не переписывать, не трогать namespace)

### Ключевые правила (выучены на блоках F/G HeatLossRevit2)

| Правило | Почему |
|---------|--------|
| Не встраивать полный код — инвентарь | Облачный ИИ обрезает ответ при большом объёме |
| Просить решения таблицами (MOVE/KEEP+причина) | Маленький ответ, нет риска обрезки |
| Просить PowerShell-скрипты вместо копий файлов | Скрипт компактен, применим и проверяем |
| Чанкинг 10-15 файлов на запрос | Ответ < лимита вывода — гарантия полноты |
| Двухфазно: сначала план, потом скрипты | План маленький и надёжный; скрипты по чанкам |
| Контракт полноты в каждом ТЗ | Мгновенная проверка ответа до применения |
| Запрет переписывания файлов целиком | Экономия вывода, меньше обрезок |
| Чек-лист слоёв (DI, XAML, NuGet, пересечения) | ИИ отвечает «проверил/не проверил» явно |
| Дать актуальный контекст (git-хэш, структура) | ИИ не выдумывает состояние проекта |
| Дать эталон формата ответа | ИИ копирует успешный образец |

## 3. Запуск роутинга (браузер + облачный ИИ)

### Qwen (chat.qwen.ai) — рекомендуется

```bash
cd E:\ПлагиныРевит\LocalAssitent
# Запустить Edge с remote debugging (порт 9222)
python scripts/qwen_task.py --file task.md --prompt "Выполни ТЗ" --output qwen_answer.md
```

QwenClient делает: открывает чат → загружает файл drag-and-drop → фиксирует
получение → отправляет промпт → ждёт ответ → копирует → сохраняет markdown.

### DeepSeek Chat (chat.deepseek.com)

```bash
# Авторизация через DEEPSEEK_EMAIL / DEEPSEEK_PASSWORD (в .env)
python pipeline.py --merged context.txt          # сбор → отправка → .md
python main.py --scenario code --prompt "..."    # итеративный сценарий
```

### Требования окружения

- Edge с remote-debugging-port=9222 (config DEBUG_PORT)
- Авторизация: первый запуск может потребовать ручного входа (CAPTCHA)
- Python 3.10+, selenium, pywin32 (см. requirements.txt)

## 4. Проверка ответа на полноту (ОБЯЗАТЕЛЬНО!)

Облачные ИИ **обрезают и искажают** большие ответы — это подтверждено на практике
(блок F: ClimateDataRepository 1844 из 8348 строк; блок G: 9 файлов с диффами).

### Чек-лист проверки

1. [ ] Есть ли `### SUMMARY` с числом файлов и строками каждого?
2. [ ] Каждый файл заканчивается `// END OF FILE`?
3. [ ] Сверь количество строк файлов с оригиналом (инвентарь из ТЗ)
4. [ ] Нет ли «...` / «(пропущено)» / «файл не изменён» заглушек?
5. [ ] Все запрошенные секции (MOVE/KEEP, маппинг, потребители) присутствуют?
6. [ ] Кодировка: .cs с BOM, без искажений кириллицы?

### Автоматическая сверка

```bash
# Скрипт сверки: имена файлов и количество строк в ответе vs оригинал
python scripts/verify_response.py response.md --against source_dir
```

(если такого скрипта нет — сделай простую сверку глазами по SUMMARY)

## 5. Применение ответа (apply-скрипт)

НЕ копируй файлы из ответа вручную — это самый частый источник ошибок.

Напиши `apply_blockN.ps1` который:
1. Парсит ответ по секциям (заголовок `### путь/файл.ext` + блок кода)
2. Извлекает содержимое в файлы (с BOM для .cs)
3. Пишет лог: какие файлы применены, какие пропущены
4. В конце — сверка количества применённых файлов с SUMMARY

```powershell
# apply_blockF.ps1 (пример структуры)
$response = "AI_TASK_BlockF_Responce.md"
$outDir = "E:\ПлагиныРевит\HeatLossRevit2\RevitServices\ProjectSettings"
# ... парсинг секций ```csharp ... ```
# ... запись файлов, добавление BOM ...
```

## 6. Верификация после применения

Локальная сборка и тесты — единственный источник истины:

```bash
# Сборка (пример для HeatLossRevit2)
& "C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" HeatLossRevit.sln -p:Configuration=Debug -p:DeployAddin=false

# Тесты
vstest.console.exe Test\bin\Debug\Tests.dll
```

### Что проверять

- Сборка всех проектов EXIT 0
- Тесты: количество падений НЕ УВЕЛИЧИЛОСЬ (сравни с базой до применения)
- Git: рабочее дерево чисто (только ожидаемые изменения)

## 7. Типичные ошибки и их устранение

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Ответ обрезан | Слишком большой запрос | Чанкинг, инвентарь вместо кода |
| Файл пустой в ответе | ИИ пропустил секцию | Контракт полноты, повторный запрос |
| Имя файла изменено | ИИ «улучшил» пути | Сверка по SUMMARY, фикс вручную |
| Кодировка сломана | UTF-8 без BOM | Применяй с BOM через скрипт |
| Namespace не переименован | ИИ забыл | Проверка сборкой + sed-замена |
| Браузер не открылся | Edge не в debug-режиме | Запусти Edge с --remote-debugging-port=9222 |

## Итоговая схема работы

```
[проект] → merge_docs → context.txt
        → task-template.md → ТЗ (с контрактом полноты)
        → qwen_task.py / pipeline.py → браузер → облачный ИИ
        → qwen_answer.md / deepseek_analysis.md
        → ПРОВЕРКА полноты (SUMMARY + END OF FILE)
        → apply.ps1 → файлы на диск (с BOM)
        → сборка + тесты → done
```
