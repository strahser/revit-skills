## 4. Формат ответа (СТРОГО)

Ответ — ТОЛЬКО следующие секции, без лишнего текста:

### 4.1 Решения
Таблица: MOVE / KEEP + причина для каждого файла из п.3.1.

### 4.2 Маппинг namespace
| Старый | Новый |
|--------|-------|
| MainAppHeatLoss.X | RevitServices.X |

### 4.3 Скрипт переноса (PowerShell)
Один блок кода с `Move-Item`/`sed`-заменами — НЕ файлы целиком.

### 4.4 Список потребителей с usings
| Файл | Добавить using |
|------|----------------|

### 4.5 Риски
Список: DI-регистрации, XAML xmlns, NuGet-пакеты, пересечения namespace,
статические вызовы — по каждому: «проверено / не проверено».

## 5. Контракт полноты (ОБЯЗАТЕЛЬНО!)

1. Каждый упомянутый файл в скриптах заканчивается строкой `// END OF FILE`.
2. В конце ответа — блок:

```markdown
### SUMMARY
total_files: N
файл1.cs: 1234 строк | END OK
файл2.cs: 567 строк | END OK
```

3. Если файл не изменён — НЕ включай его в ответ (только укажи в SUMMARY).

## 6. Ограничения (что НЕ делать)

- ❌ НЕ переписывай файлы целиком в ответе — только скрипты и таблицы
- ❌ НЕ меняй имена namespace, не указанные в п.4.2
- ❌ НЕ удаляй и не переименовывай файлы без явного указания
- ❌ НЕ добавляй «...` или «(пропущено)» — лучше явно пометить файл как пропущенный
- ✅ Кодировка скриптов: ASCII (PowerShell 5.1 не понимает кириллицу в путях)

## 7. Эталон формата (образец успешного ответа)

```
### RevitServices/ProjectSettings/SomeService.cs
```csharp
// ... только если файл МЕНЯЕТСЯ — и то лучше через скрипт
```

### Скрипт переноса
```powershell
Move-Item "MainAppHeatLoss\X\File.cs" "RevitServices\ProjectSettings\File.cs"
```

### SUMMARY
total_files: 60
```
