# Revit Skills Orchestrator — инструкция по использованию

Как запускать миссии, работать с окном промпта, хранилищем и ревью в проекте `revit-skills`.

## 1. Что такое Revit Skills Orchestrator

**Revit Skills Orchestrator** — это плагин `opencode-orchestrator` v1.7.10 для OpenCode,
реализующий мультиагентный цикл управления задачами:

```
Commander → Planner → Worker → Reviewer
```

- **Commander** — ставит миссию, планирует итерации, делегирует подзадачи;
- **Planner** — разбивает миссию на подзадачи, исследует и документирует (docs/brain);
- **Worker** — реализует: пишет код, документы, тесты, доказательства;
- **Reviewer** — независимо проверяет выполнение, пишет ревью в БД.

**Состояние миссии** плагин хранит в `.opencode/`:

| Файл | Назначение |
|------|-----------|
| `todo.md` | задачи (single source of truth) |
| `context.md` | контекст миссии (инструкции, что сделано) |
| `mission-ledger.jsonl` | журнал решений |
| `docs/brain/` | память (scratchpad, memories) |
| `project.db` | SQLite-хранилище: миссии, задачи, проблемы, документы, ревью |

**SQLite-хранилище** — `.opencode/project.db` — доступно через MCP-сервер `storage`
(см. раздел 4). **Дашборд** — `node .opencode/dashboard.mjs` → http://localhost:4317
(вкладки: Скилы, Wiki, База данных, Миссия, Промпт).

## 2. Как запустить миссию (команда /task)

В TUI opencode ввести:

```bash
/task "Описание задачи"
```

Это создаёт новую миссию (M-N) или продолжает активную. Плагин запускает
mission loop: Commander планирует → Planner разбивает → Worker делает → Reviewer проверяет.

**Управление:**

| Команда | Действие |
|---------|----------|
| `/task "..."` | создать/возобновить миссию |
| `/cancel` | деактивировать текущую миссию |
| `/stop` | остановить выполнение |
| `/agents` | показать загруженных агентов |

**«Каждый раз внутри сессии использовать команду task?»** — НЕТ. Миссия **персистентна**:
`/task` с новым текстом создаёт или возобновляет миссию, а дальше она продолжается
автоматически до завершения или `/cancel`. Повторно вызывать `/task` внутри сессии
не нужно — цикл идёт сам.

## 3. Окно промпта (Дашборд → вкладка «Промпт»)

1. Открыть дашборд: `node .opencode/dashboard.mjs` → http://localhost:4317
2. Перейти на вкладку **«Промпт»**
3. В `<textarea>` написать описание миссии
4. Кнопка **«Сохранить черновик»** — сохраняет в `.opencode/prompt-drafts.json`
5. Кнопка **«Копировать /task»** — генерирует `/task "твой текст"` и копирует в буфер обмена
6. Вставить в терминал opencode → Enter → миссия стартует

Список сохранённых черновиков доступен для повторного использования:
кнопки **«Загрузить»** (заполняет textarea) и **«Копировать /task»**.

Черновики хранятся отдельным JSON-файлом `.opencode/prompt-drafts.json` —
дашборд работает с `project.db` только на чтение (readOnly).

## 4. Где хранятся исходники базы данных

| Что | Путь |
|-----|------|
| Файл БД | `.opencode/project.db` (SQLite) |
| Схема | `.opencode/schema.sql` |
| MCP-сервер | `.opencode/storage-mcp.mjs` (Node built-in `node:sqlite`, без зависимостей) |

**Таблицы:** `missions`, `tasks`, `progress_log`, `problems`, `documents`, `review_rounds`.

**Инструменты MCP storage:**

| Инструмент | Назначение |
|-----------|------------|
| `storage_init` | создать таблицы (автоматически) |
| `storage_query` | только SELECT (чтение) |
| `storage_execute` | INSERT/UPDATE/DELETE/DDL (один оператор) |
| `storage_state` | снимок проекта |
| `storage_mission` | begin/update/complete миссии |
| `storage_task` | добавить/обновить подзадачу |
| `storage_problem` | записать/закрыть проблему |
| `storage_document` | сохранить документ (file/link/text) |
| `storage_review` | записать раунд ревью |

**Прямые SQL-запросы** к `.opencode/project.db` возможны (readOnly для чтения),
но предпочтительно работать через MCP `storage`.

## 5. Коммиты на GitHub — делает ли оркестратор?

**Оркестратор (плагин) НЕ делает коммиты и НЕ пушит автоматически.**
Коммиты выполняют **агенты внутри миссии** по инструкции задачи
(см. `.opencode/wiki/agent-workflow.md`):

```bash
cd E:\ПлагиныРевит\revit-skills
git pull
git add -A
git commit -m "описание изменений"
git push
```

- Репозиторий: `strahser/revit-skills`, remote `https://github.com/strahser/revit-skills.git`
- Ветка: `main` (force-push не использовать)
- Агент делает commit/push, если задача включает «закоммитить и запушить»

## 6. Глобальные промпты проекта — как убедиться, что оркестратор их обрабатывает

Глобальные промпты = системные инструкции, загружаемые в каждую сессию:

1. `opencode.json` → `"instructions": ["AGENTS.md", ".opencode/wiki/index.md"]`
   — эти файлы подгружаются как system prompt в начале сессии.
2. Skills: `.opencode/skills/` — подгружаются автоматически при совпадении задачи.

**Как проверить:**

1. Открыть `opencode.json` — убедиться, что `instructions` указывает на актуальные файлы;
2. При старте новой сессии opencode — в начале контекста видны содержимое
   `AGENTS.md` и `wiki/index.md` (они печатаются в системном промпте);
3. Команда `/agents` показывает загруженных агентов и их промпты;
4. В дашборде вкладка «Миссия» → `context.md` содержит инструкции текущей миссии.

## 7. Типичный workflow

1. Открыть дашборд: `node .opencode/dashboard.mjs` → http://localhost:4317
2. Вкладка **«Промпт»** → написать задачу → **«Копировать /task»**
3. В терминале opencode → вставить → Enter
4. Следить в дашборде:
   - вкладка **«Миссия»** — `todo.md`, `context.md` плагина;
   - вкладка **«База данных»** — дерево миссий/задач/ревью.
5. После завершения (Reviewer passed) → агент делает git commit/push
   по `agent-workflow.md`.

## 8. Частые ошибки / советы

- **Не запускать несколько `/task` параллельно** — одна активная миссия;
- Если застряло — `/cancel` и новый `/task`;
- Дашборд **readOnly** — не меняет БД, только читает;
- Проблемы записываются в БД (`storage_problem`) — видны в дашборде;
- Ревью (`review_rounds`) — независимый Reviewer, статус `passed`/`failed` + `next_steps`;
- Если ревью `failed` — Commander создаёт продолжение миссии с учётом `next_steps`;
- При перезагрузке сессии: `storage_state` → активная миссия → открытые проблемы
  → `.opencode/context.md`.
